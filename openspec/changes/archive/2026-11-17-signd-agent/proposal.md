# Proposal

## Why

keychain-agent serves only Rivest–Shamir–Adleman (RSA) keys from the login keychain.
Each signature takes about 36 ms.
The keychain protects the keys with an access control list (ACL), and any binary that the release team signs can use them.

It cannot generate keys or use the Secure Enclave, and it needs per-key setup outside the agent.
signd replaces it with a general SSH agent.
Its keys are usable only by signd, are kept in the Secure Enclave or wrapped by it, and are served from memory in milliseconds.

## What Changes

- **BREAKING**: The project, binary, socket and identifier become `signd`.
  The release is an app bundle, `Signd.app`, signed with a Developer ID provisioning profile, and the cask links `signd` onto the `PATH`.
- **BREAKING**: Keys move from the login keychain to the data-protection keychain, in an access group only signd's signed binary can claim.
  Login-keychain keys are no longer served.
- New: Secure Enclave P-256 keys, generated by `signd key create`, that never leave the Mac.
- New: a resident agent that the app registers as its own LaunchAgent, serving `~/.ssh/signd.sock` with the RFC 9987 messages for list, sign, add, remove and extensions.
- New: a command-line interface for keys and service: `create`, `list`, `show`, `delete`, `service enable`, `service disable`, `status`, `config`, `serve`.
- Removed: the login-keychain lookup by label, and the dotfiles LaunchAgent and per-key import script it needed.

Importing existing keys (Ed25519 and RSA, wrapped by the Secure Enclave) is the `wrapped-keys` change.
Syncing keys from 1Password and writing the SSH host configuration is the `onepassword-sync` change.

## Capabilities

### New Capabilities

- `agent-protocol`: the socket, the SSH agent messages signd answers, and who may connect.
- `key-store`: where keys live, who can use them, and how long private keys stay in memory.
- `cli`: the `signd` commands and their output.
- `packaging`: the signed app bundle, its provisioning profile, the package and the LaunchAgent.

### Modified Capabilities

- `keychain-agent`: every requirement is removed; `agent-protocol`, `key-store` and `packaging` replace it.

## Impact

- Code: `Sources/` is restructured into SwiftPM targets for the message format, the protocol, the store, the server and the executable.
  New dependencies: SwiftNIO, swift-crypto (`CryptoExtras`) and swift-argument-parser.
- Release: the package job builds and signs an app bundle.
  The bundle has an embedded Developer ID provisioning profile, which the job takes from the signing secrets.
  The cask changes from a binary in `/usr/local/bin` to an app in `/Applications` plus a linked command.
- Tests: protocol tests run on GitHub-hosted runners.
  The runners have no Secure Enclave, so Secure Enclave and keychain tests run on a physical Mac before each release.
- Users: Macs running keychain-agent keep it until the `wrapped-keys` change can import their RSA keys into signd.
